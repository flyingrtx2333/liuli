# Electron 替代目标与验收门槛

日期：2026-10-27。本文是工程验收计划，不是兼容性承诺。历史能力表保留 v0.3 起点；当前已交付 v0.5 Linux 切片，v0.6 合并代码已完成记录范围内的最终实窗验收，不能把历史表误读成当前实现状态。

## “取代”的工作定义

目标是：同一套显式声明和应用逻辑，构建可分发的 Windows、macOS、Linux 桌面应用；在明确业务场景中具备相同任务能力、交互质量和可访问性，并通过同等负载的资源测试。优先原生轻量应用，不内嵌 Chromium。

这不自动等于运行未经修改的 Electron 项目。Electron 的 BrowserWindow 可以加载 HTML/URL；其主进程使用 Node.js，窗口内容运行在独立渲染进程。现有 HTML/CSS/JS、DOM、Node 插件和网页嵌入需要另一个兼容层或迁移工程，当前没有实现，也不能把它们悄悄从“完整兼容”的定义中排除。参见 [BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window) 与 [进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)。

因此，允许的完成声明应是“已替代某个具名应用/工作负载，覆盖列出的平台和能力”，而不是“彻底替代所有 Electron 应用”。若未来要求原项目零改动运行，需要明确重估 Web/Node 兼容路线及资源代价。

## 当前进度（2026-10-27）

- 已交付 v0.5：响应式布局、不可变共享存储、文字整形/字素编辑、显式异步持久化、可选 Linux AT-SPI 桥；43 项 Python 测试和 3 项原生 CTest，以及记录中的真实桌面流程通过。
- v0.6 合并源代码 `3007dde`：多字段事务编辑、声明式按钮禁用、可访问文本几何、独立持久化修订计数。56 项自动测试通过；自定义表单的 2 项适用 CTest 通过，计数器专用 GUI smoke 不对自定义表单冒充验收。最终合并版本的双字段编辑、独立撤销重做、保存/加载/重启、AT-SPI 字符几何和按钮禁用实窗流程通过，详见 evidence/v0.6-integrated；镜像/隐藏状态等边界仍只计自动化覆盖。
- Windows 已获准在独立目录验证，但原代理无法连接，下载和构建尚未进行；macOS 测试访问仍待授权。两者均不能标记支持。
- 完整读屏器/真实系统 IME、三平台安装分发、同负载能耗对照仍未完成；一次关闭时 X11 错误保持开放调查。
- Qt Widgets 只完成隔离可行性实验，未并入主线；原生编辑历史与失败模型事务的原子一致性尚未解决，不能直接迁移后端。

## 历史证据基线（v0.3）

| 能力 | v0.3 状态 | 通过下一门槛需要的证据 |
|---|---|---|
| 显式类型、纯依赖、事务更新 | 已有编译检查和回滚测试 | 保留全部旧测试，新增大模型共享存储隔离与失败回滚；测同负载分配量 |
| 原生桌面窗口 | Linux X11 云端实窗已验证 | 同一示例在 Windows/macOS 真正构建、启动、交互、关闭；不是仅交叉编译 |
| 布局 | 固定画布整体缩放 | 最小/常规/大窗口真实重排，布局与命中一致，文字不随窗口被拉扁；这是当前实施中的门槛 |
| 按钮、搜索、列表 | 简单单窗口已验证 | 可复用控件状态、禁用/焦点/滚动边界测试；多视图组合，不依赖演示 ID |
| 文本编辑 | 末尾追加、UTF-8 码点退格 | 光标/选区/粘贴/撤销；中文候选与预编辑取消；组合字符/emoji 不拆坏；复杂文字排版 |
| 无障碍 | 未实现，Tab 不等于屏幕阅读器 | 角色、名称、值、焦点、动作暴露到平台辅助树；真实读屏器完成任务 |
| 应用效果与 I/O | 未实现 | 界面不中断的异步读写，取消/错误/重复提交，原子保存和重启恢复 |
| 系统能力 | 除窗口/输入外未实现 | 按目标应用引入文件对话框、菜单、剪贴板、通知、托盘、链接、拖放；逐项平台测试 |
| 多窗口与生命周期 | 未实现 | 关闭顺序、模态阻塞、父子窗口、后台任务取消、退出后无残留进程 |
| 安全边界 | 可信 DSL 验证；非沙箱 | 外部输入限额、效果能力白名单、错误隔离；不允许任意网络内容直接取得本机权限 |
| 分发/更新 | 源码 ZIP，非安装包 | 每个平台可安装/卸载包，依赖清单、许可证、签名/更新回滚策略及实际测试 |
| 性能/能耗 | 单个 Linux 场景 RSS/CPU 观察 | 同功能、同数据、同机器、相同交互轨迹的对照；启动、内存、p50/p95 延迟、空闲、长时泄漏、真实能耗分别测量 |

这些类别来自实际应用能力，而不是要求照抄 Electron API。Electron 提供[文件对话框](https://www.electronjs.org/docs/latest/api/dialog)和[系统剪贴板](https://www.electronjs.org/docs/latest/api/clipboard)；应用必须根据迁移任务覆盖相应行为。它也利用 Chromium 辅助树与系统辅助技术交互，见[无障碍说明](https://www.electronjs.org/docs/latest/tutorial/accessibility)。原生自行绘制不能把这些能力视为免费获得。

## 顺序与退出条件

### 门槛 A：可用的单窗口原生 UI（Linux 已有切片证据）

交付响应式布局与事务复制优化，保留当前示例功能。退出条件：全套回归通过；至少三档尺寸实窗操作；每次提交的复制成本可说明；错误不会损坏状态。只到这一步仍是框架原型。

### 门槛 B：真实本地文档应用（紧接 A）

两个可独立推进的小切片：

1. **文本编辑内核 + 输入适配**：先独立、可测试的单行编辑状态（caret/anchor、选择替换、删除、撤销/重做），再接 SDL 文本/剪贴板/组合输入事件。把字节、码点、字素簇、绘制位置区分清楚。退出条件为中文与 emoji 编辑、选区替换、粘贴限额、组合输入取消/提交、焦点切换不重复提交；未实际验证系统 IME 时必须仍标“未验证”。渲染需采用成熟文字整形/字体回退库，而不是扩大 Cairo toy-text 的能力声明。
2. **受约束异步效果 + 持久化**：用仅访问指定文档路径的本地便笺/清单示例，串起读取、编辑、保存、关闭重开。I/O 不阻塞 UI；任务有 ID/取消，晚到结果不能覆盖新状态；保存使用临时文件加原子替换，失败保留原文件。退出条件：连续操作、拒绝访问、损坏/超大输入、取消、重复保存、异常退出后的恢复；测试只用项目临时目录，不触碰真实用户资料。

B 的明确交付物不是另一个计数器截图，而是一个可关闭重启、不会丢失已保存数据的小应用。高级网络、多媒体、插件先不加入，除非具名迁移目标需要。

### 门槛 C：三平台构建、分发与可访问性

将 B 的同一应用在三平台运行。逐平台记录工具链、架构、依赖、构建日志、安装/卸载和系统输入测试。签名、开发者证书、付费云构建、上架和发布需要对应授权，不能由当前研发任务隐含获得。Electron 自身也把[打包](https://www.electronjs.org/docs/latest/tutorial/application-distribution)作为分发步骤，而非编译成功即完成。

无障碍不能推迟到“正式发布以后”：至少键盘全流程、平台辅助树和一套真实读屏任务通过后，才可称普通桌面应用可用。保留错误诊断和崩溃定位信息，同时默认不收集用户内容。

### 门槛 D：具名应用迁移与对照

选择一个用户愿意迁移的真实应用，列出它依赖的能力与测试数据；先完成全流程，再对照 Electron 版本。资源目标需由实测确定，不预设“零功耗/十倍快”。全部任务完成、数据一致、错误恢复和平台验收通过后，才宣布该应用已被替代。不同类别（IDE、聊天、多媒体编辑、网页容器）分别验收，不能拿本地便笺成绩外推。

## 架构约束

- 纯模型/布局与有副作用的系统操作分离；效果通过明确能力与类型边界进入。
- 不以牺牲回滚、安全、字体正确性或可访问性换取好看的小样本内存数字。
- 不重新发明浏览器兼容层来暗中恢复全部 Chromium 成本；需要 Web 嵌入时明确独立方案及成本。
- 当前原生进程不是沙箱。将来处理外部内容、脚本或插件时需要单独隔离设计。Electron 的[安全指南](https://www.electronjs.org/docs/latest/tutorial/security)同样强调本地系统权限使风险扩大；“没有 JS”并不等于没有安全问题。
- 每个门槛以代码、可复现测试和实际运行证据关闭；未满足的依赖明确列出，不靠持续新增功能规避验收。

## 平台准备的实际限制

本次云端只有 Linux C++ 编译器和 SDL2/Cairo 运行库。检查未发现 macOS SDK、xcrun、Windows MinGW/MSVC 或 Wine。SDL 官方提供多平台构建路径，但依赖支持不等于本项目已经可用，见 [SDL2 安装说明](https://wiki.libsdl.org/SDL2/Installation)。

当前新增 CMake 构建会在 Linux 验证；其他平台只能称“构建入口准备”，直到该平台实际日志与交互验收存在。最小真实路径：在有 Xcode/SDK 的 macOS 构建机、以及有 MSVC 或 MinGW 与相同依赖的 Windows 构建机，编译同一生成代码并运行同一应用。Linux 交叉编译即使成功也不能代替系统 IME、无障碍、窗口生命周期和安装测试。

当前不能仅靠这里的 Linux 工具链诚实关闭三平台验收。用户已授权 Windows 独立目录测试，但网络路线仍阻塞；macOS 尚待授权。继续完成 Linux 验证和可移植构建，不修改代理或擅用未授权电脑。
